Original CVDP problem statement:
```
The **Greatest Common Divisor (GCD)**, also known as the Greatest Common Factor (GCF) or Highest Common Factor (HCF), is the largest positive integer that divides two or more integers without leaving a remainder.

Create an RTL design with SystemVerilog, consisting of modules **gcd_top**, **gcd_controlpath** and **gcd_datapath** that computes the GCD of two inputs `A` and `B` using the Euclidean algorithm. 
The Euclidean algorithm calculates the GCD by iteratively replacing the larger of two numbers with the difference between the two numbers. This process is repeated, reducing the larger number each time, until the two numbers become equal. At this point, the value of either number is the GCD of the original inputs. The module should be designed with a finite state machine (FSM) to control the computation and a datapath to perform arithmetic operations. The result of the computation is output as soon as the calculation completes, along with a signal indicating completion. The detailed design specification is given below :

### **Design Specification** :
---
### **Functional Requirements**:

- **Computation**: 
  - The complete design computes the GCD of two unsigned integers `A` and `B` using Euclidean algorithm.

- **Integration**:
   - The top-level module `gcd_top` should instantiate the control path and datapath modules `gcd_controlpath` and `gcd_datapath` and connect the signals.
   - The `go` signal should initiate the computation, and the result should be available at the `OUT` output when `done` is set to active high.
 
- **Control Path Design**:
   - Use a finite state machine (FSM) to control the computation flow. It should manage the `done` signal and determine when to perform subtractions based on the results of the comparisons (`A == B` or `A > B`).
 
- **Datapath Design**:
   - The datapath should handle the arithmetic operations (subtraction and comparison) and provide the final result `OUT`.
   - It should store intermediate values of `A` and `B` and send comparison results to the control path. 

---

### **RTL Module Requirements**:


### **1. GCD Control Path Module (`gcd_controlpath`)**:

The control path handles the state transitions of the GCD computation process using a finite state machine (FSM).

- **Parameters**:

     - `WIDTH` (Default 4, must be greater than 0): Bit-width of `A`, `B` and `OUT `.
     
- **Inputs**:
  - `clk`: Clock signal. The design should be synchronized to the positive edge of this clock signal.
  - `rst`: Active high Synchronous reset signal.
  - `go`: Start signal for GCD computation. Active high.
  - `equal`: Signal from the datapath indicating that `A == B`. Active high.
  - `greater_than`: Signal from the datapath indicating `A > B`. Active high.

- **Outputs**:
  - `controlpath_state [1:0]`: Current FSM state sent to the datapath to control its operations.
  - `done`: Signal indicating that the computation is complete (`A == B`). Active high.

- **FSM States**:
  - **S0 (IDLE)**: Wait for `go` to be set to high. No operation until `go` is received.
  - **S1 (DONE)**:Set  `done` to high when `A == B`. Return to `S0` after output is provided.
  - **S2 (A > B)**: Control the datapath to subtract `B` from `A`.
  - **S3 (B > A)**: Control the datapath to subtract `A` from `B`.
  - **Default**: Transition to S0 state, without performing any computation.

- **Behavior**:
  - Output `controlpath_state` signal to communicate the current FSM state to the datapath, instructing it which operation to perform.
  - The `done` signal is set to active high for one clock cycle to indicate the completion of the operation when the `equal` signal from the datapath is received.
  - Both output signals should be synchronized to the positive edge of the clock.

### **2. GCD Datapath Module (`gcd_datapath`)**:

The datapath performs the arithmetic operations required by the Euclidean algorithm, such as comparing `A` and `B` and updating their values.

- **Parameters**:

     - `WIDTH` (Default 4, must be greater than 0): Bit-width of `A`, `B` and `OUT `.
     
- **Inputs**:
  - `clk`: Clock signal. The design should be synchronized to the positive edge of this clock signal.
  - `rst`: Active high Synchronous reset signal.
  - `A [WIDTH-1:0]`: input value A (unsigned and non-zero).
  - `B [WIDTH-1:0]`: input value B (unsigned and non-zero).
  - `controlpath_state [1:0]`: The current state of the control path FSM.

- **Outputs**:
  - `OUT [WIDTH-1:0]`: output holding the GCD value (unsigned). The value of `OUT` is updated every time the `done` signal is asserted. 
  - `equal`: Signal indicating that `A == B`. Active high.
  - `greater_than`: Signal indicating that `A > B`. Active high.

- **Behavior**:
  - Latches the input values `A` and `B` into internal registers `A_ff` and `B_ff`, for manipulation when the control path initiates a new computation.
  - The `equal` and `greater_than` signals are generated using combinational logic based on the values of `A` and `B` in the `S0` state and the values of `A_ff` and `B_ff` in all other states by continuously comparing the values of `A_ff` and `B_ff` as directed by the controlpath_state signals. These 2 signals are sent back to the control path to guide state transitions.
  - Based on control signals, at each clock cycle repeatedly subtracts the smaller value from the larger until `A_ff` and `B_ff` are equal.
  - Based on control path signals, the GCD result is assigned to `OUT` at the positive edge of the clock when the computation is complete.

### **3. GCD Top Module (`gcd_top`)**:

The top-level module integrates the control path and datapath modules. It receives the inputs, manages the computation process, and outputs the GCD.

- **Parameters**:

     - `WIDTH` (Default 4, must be greater than 0): Bit-width of `A`, `B` and `OUT `.

- **Inputs**:
  - `clk`: Clock signal. The design should be synchronized to the positive edge of this clock signal..
  - `rst`: Active high synchronous reset signal.
  - `A [WIDTH-1:0]`: input value A (unsigned and non-zero). 
  - `B [WIDTH-1:0]`: input value B (unsigned and non-zero).
  - `go`: Start signal to initiate GCD calculation. Active high.

- **Outputs**:
  - `OUT [WIDTH-1:0]`: output for the calculated GCD (unsigned) from `gcd_datapath`.
  - `done`: Signal that indicates when the computation is complete from `gcd_controlpath`. 

### **Design Constraints**:

- **Input Constraints**:
  - Inputs `A` and `B` must be stable and valid before setting the `go` signal to active high.
  - Both `A` and `B` are unsigned integers (range 1 to 2<sup>`WIDTH`</sup>-1). The GCD module only supports this range for computation.
  - `clk` must be a stable clock signal, and `rst` must be used to reset internal registers, FSM states and outputs to the initial state.
  - Assume that `go` is high for 1 clock cycle for every new input `A` and `B`. The `go` for a new input will be provided only from the next cycle following the assertion of `done` signal to high, indicating that the computation for the previous inputs is complete.

- **Output Constraints**:
  - The `OUT` signal is valid and updated only along with assertion of `done` to high. Otherwise, it holds the previously computed GCD value. The `OUT` signal is reset to 0 when `rst` is active high.
  - The `done` signal goes high for 1 clock cycle to indicate completion of computation. The `done` signal goes low when `rst` is active high.

- **Latency and Timing**:
   - The design can have different latencies for different inputs. The best case occurs when `A == B` from the start (2 cycles), and the worst case occurs when A = 1 and B =  2 <sup>WIDTH</sup>-1  ( 2<sup>WIDTH</sup>+1 cycles).
   
- **Example operation**:
  - For `WIDTH`=16:  Inputs are `A`=4, `B`=2, `go` asserted high for 1 cycle
  - `OUT`=2 and `done`=1(for 1 clock cycle)
```
