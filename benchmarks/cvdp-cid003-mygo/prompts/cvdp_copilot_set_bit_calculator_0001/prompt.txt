Original CVDP problem statement:
```
Design a **Set Bit Calculator** module in verilog that counts the number of `1` bits (set bits) in a bitstream received at the positive edge of a clock signal (`i_clk`) when the `i_ready` signal is asserted. The output count (`o_set_bit_count`) will be updated until the `i_ready` signal deasserts, at which point the output reflects the total count of `1` bits received. The count resets to `0` when the `i_ready` signal asserts again or an asynchronous active-low `i_rst_n` signal is triggered.

## Parameters
- `p_max_set_bit_count_width` (default = 8): The maximum bit-width of `o_set_bit_count`. This limits the count value to `2^p_max_set_bit_count_width - 1`.

## Input/Output Specifications
### Inputs:
- `i_bit_in` (1 bit): The single-bit stream input.
- `i_clk` (1 bit): Clock signal for synchronization.
- `i_ready` (1 bit): Synchronous signal that enables bit counting when asserted (`1`).
- `i_rst_n` (1 bit): Active-low asynchronous reset signal.

### Outputs:
- `o_set_bit_count` (`p_max_set_bit_count_width` bits): Total count of `1` bits received in the bitstream since the last reset or `i_ready` assertion. If the count exceeds the maximum value (`2^p_max_set_bit_count_width - 1`), it saturates.

## Assumptions and Constraints
1. The bit count updates only when `i_ready` is high and `i_bit_in` is sampled on the rising edge of `i_clk`.
2. The count halts and retains its value when `i_ready` deasserts.
3. The count resets to `0` when:
   - `i_rst_n` is asserted low (asynchronous reset).
   - `i_ready` asserts again after being deasserted.
4. It saturates at this maximum value if the count exceeds `2^p_max_set_bit_count_width - 1`.
5. The 1st bit after `i_ready` goes high will be ignored for set bit calculation.

## Behavioral Definitions
1. When `i_rst_n` is low, the `o_set_bit_count` must asynchronously reset to `0`.  
2. On the positive edge of `i_clk`, if `i_ready` is high, `o_set_bit_count` increments by 1 for each `i_bit_in` that is `1`, up to the saturation limit.  
3. When `i_ready` transitions from low to high, the `o_set_bit_count` resets to `0`.  

## Timing and Synchronization
1. `i_ready` is synchronous to `i_clk`.  
2. `i_rst_n` is asynchronous and active-low.  
3. Counting occurs on the rising edge of `i_clk` when `i_ready` is high.  

## Task Requirements
1. Define a Verilog module named `SetBitStreamCalculator`.  
2. Implement the behavior described using sequential logic.  
3. Include:
   - Handling of the asynchronous reset.
   - Proper synchronization for `i_ready`.
   - Saturation logic for `o_set_bit_count` based on `p_max_set_bit_count_width`.
4. Provide a testbench to validate:
   - Reset functionality (`i_rst_n`).
   - Behavior during `i_ready` assertion and deassertion.
   - Correct counting of `1` bits in the input stream.

## Example Scenarios
### Scenario 1: Counting set bits with default `p_max_set_bit_count_width = 8`
**Inputs:**  
- `i_clk = 50 MHz`, `i_ready = 1`, `i_rst_n = 1`, `i_bit_in` transitions: `1, 0, 1, 1` (sampled on `i_clk`).  
**Output:**  
- `o_set_bit_count = 3` after the last bit.

### Scenario 2: Reset Behavior  
**Inputs:**  
- `i_rst_n` transitions low while counting.  
**Output:**  
- `o_set_bit_count` resets to `0` immediately.

### Scenario 3: Saturation at maximum count  
**Inputs:**  
- `p_max_set_bit_count_width = 4` (maximum value = 15).  
- `i_clk = 50 MHz`, `i_ready = 1`, `i_rst_n = 1`, `i_bit_in` transitions: `16 consecutive 1's`.  
**Output:**  
- `o_set_bit_count = 15` (saturation).

## Testbench Considerations

  - `i_ready` deasserted in the middle of counting.
  - Multiple transitions of `i_rst_n` during operation.

- Test for saturation when `o_set_bit_count` reaches the maximum value defined by `p_max_set_bit_count_width`.
```
