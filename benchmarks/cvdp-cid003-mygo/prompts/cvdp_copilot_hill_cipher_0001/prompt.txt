Original CVDP problem statement:
```
Design an RTL module that implements the Hill cipher encryption algorithm with the following specifications:

- **Block Size**: 3 letters (each letter represented by 5 bits).
- **Key Matrix**: 3x3 matrix (each element represented by 5 bits).
- **Modular Arithmetic**: All operations are based on modulo 26.

The Hill cipher is a classical symmetric encryption algorithm based on linear algebra. It operates on blocks of plaintext and uses matrix multiplication to produce ciphertext.

### 1.1. Basic Concepts

- **Plaintext**: The original message to be encrypted.
- **Ciphertext**: The encrypted message.
- **Block Size**: The number of letters processed at a time. The design has to use a block size of **3**.
- **Key Matrix**: A square matrix used for encryption. For a block size of 3, the key matrix is a 3x3 matrix.
- **Modular Arithmetic**: All calculations are performed on modulo 26, corresponding to the 26 letters of the English alphabet.

### 1.2. Encryption Process

1. **Convert Letters to Numbers**: Map each letter to a number (e.g., A=0, B=1, ..., Z=25).
2. **Form Plaintext Vector**: Group the plaintext into blocks of 3 letters and represent them as column vectors.
3. **Matrix Multiplication**: Multiply the key matrix by the plaintext vector.
4. **Modulo Operation**: Apply modulo 26 to each element of the resulting vector.
5. **Convert Numbers to Letters**: Map the resulting numbers back to letters to obtain the ciphertext.

## 2. Module Specifications

### 2.1. Port Definitions

#### 1. Clock and Reset

- **`clk`**: Clock signal for synchronous operation. 
- **`reset`**: Asynchronous reset signal to initialize the module. Set the output `ciphertext` to 0 when the `reset` is HIGH.

#### 2. Control Signals

- **`start`**: A logic HIGH in this input initiates the encryption process.

#### 3. Data Inputs

- **`plaintext`**: 15-bit input representing 3 plaintext letters.
  - Each letter is represented by 5 bits.
  - Bit mapping:
    - `plaintext[14:10]`: First letter.
    -  `plaintext[9:5]`: Second letter.
    - `plaintext[4:0]`: Third letter.

- **`key`**: 45-bit input representing the 3x3 key matrix.
  - Each element is represented by 5 bits.
  - key value should vary from 00000 to 11001.
  - Element mapping:
    - `key[44:40]`: K <sub>00</sub>
    - `key[39:35]`:  K <sub>01</sub>
    - `key[34:30]`:  K <sub>02</sub>
    - `key[29:25]`:  K <sub>10</sub>
    - `key[24:20]`:  K <sub>11</sub>
    - `key[19:15]`:  K <sub>12</sub>
    - `key[14:10]`:  K <sub>20</sub>
    - `key[9:5]`: K <sub>21</sub>
    - `key[4:0]`:  K <sub>22</sub>

#### 4. Data Output

- **`ciphertext`**: 15-bit output representing the encrypted 3 letters.
  - Bit mapping follows the same pattern as `plaintext`.
- **`done`**: A HIGH in this output signal indicates that the encryption process is complete.

### 2.2. Functional Requirements

- **Finite State Machine (FSM)**: Implement an FSM to manage the encryption process.
- **Matrix Multiplication**: Compute the ciphertext vector \( C \) as:

 C<sub>i</sub> = $$\left( \sum_{j=0}^2 K_{ij} \right) \times \left( P_j \right)$$ mod26
  Where:

  - C<sub>i</sub> : i<sup>th</sup> element of the ciphertext vector.
  - K<sub>ij</sub>: Element of the key matrix at row \( i \), column \( j \).
  - P<sub>j</sub>:  j<sup>th</sup> element of the plaintext vector.

- **Modular Arithmetic**: Implement the modulo 26 operation.
- **Synchronous Operation**: All operations should be synchronized with the rising edge of the clock (`clk`).
- **Latency**: The design will have a latency of three clock cycles to produce the ciphertext after applying logic HIGH to `start`
