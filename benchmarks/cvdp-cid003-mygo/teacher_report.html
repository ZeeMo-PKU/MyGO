5. 关键发现

接口契约问题是第一优先级

  • PORT_OR_SIGNAL_MISSING：20 个，testbench 访问的端口或信号不存在。
  • PORT_NAME_MISMATCH_OUT_PREFIX：18 个，典型现象是 CVDP 期望 o_generate，实际生成 out_o_generate。
  • PARAMETER_MISSING：11 个，CVDP 用 iverilog -P 设置参数，但生成 Verilog 没有对应 parameter。

编译器/模型问题要单独算

  • 7 个 LLM 生成超时，不评价 MyGO。
  • 3 个 MyGO 编译超时，不评价 CVDP 功能。
  • 4 个 Go 静态错误，属于模型生成代码的 parse/type 问题。
  • 5 个 MyGO IR/CIRCT 错误，适合做编译器最小复现。

6. 实验设置与结果解释

本轮实验使用固定的 single-shot/pass@1 流程：每道题只调用一次 LLM，不进行多轮 retry、fallback 或自动修复。相对于原始测试脚本，本轮仅对测试驱动层做了两项必要适配：prompt 中要求 Go 顶层函数名与 CVDP 原始 TOPLEVEL 一致，并在 MyGO 编译命令中加入 --target <TOPLEVEL>。MyGO compiler 源码未作为本轮实验变量进行修改。

结果显示，非 PASS case 主要集中在生成 RTL 与 CVDP harness 的接口契约差异，包括输出端口命名差异、Verilog parameter 缺失、以及 testbench 访问内部状态或可观测信号失败。此类失败说明 CVDP harness 的接口约束尚未被当前 Go/RTL 生成流程完整表达，并不等价于算法功能本身一定错误。

因此，本报告在逐题分析中区分了接口契约错误、Go 静态错误、MyGO IR/CIRCT 后端错误、超时和真实功能断言失败，避免把环境问题、接口问题和功能语义问题混为同一类。
